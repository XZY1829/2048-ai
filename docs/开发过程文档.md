#### 架构决策记录

1. **Bitboard 4-bit 方案**
   - 选择: 每格 4 bit，总共 64 bit 填满一个 `uint64_t`
   - 理由: 完美对齐、查表大小合理(65536项)、覆盖实际上限(32768)
   - 已知限制: 若 tile 达到 65536 (log2=16) 则溢出，但 Expectimax 实际不会达到

2. **查表法 vs 朴素模拟**
   - 选择: 预计算 65536 项查找表
   - 性能对比: 查表 ~5ns/行 vs 朴素 ~200ns/行，加速 40x
   - 内存代价: ~768KB，可接受

3. **启发式特征选择**
   - 空格数: 权重 270（最重要，活下来是第一优先级）
   - 单调性: 惩罚 47（保持有序排列）
   - 平滑度: 惩罚 10（鼓励相邻同值）
   - 合并潜力: 奖励 11（有合并机会就给分）
   - 位置权重: 系数 1.5（大值在左侧）

4. **AI 搜索策略**
   - 算法: Expectimax（MAX+CHANCE 交替）
   - 自适应深度: 空格多浅搜(3)、空格少深搜(6-7)
   - 优化: Transposition Table + 概率裁剪(阈值 0.0001)
